## 1. 全体アーキテクチャ

```
┌─────────────────────────────────────────────────────────┐
│ モバイルアプリ  Expo (React Native) / TypeScript          │
│  - Googleログイン / 撮影 / グリッド閲覧 / 日報 / 勤怠      │
└───────┬─────────────────────────────────────────────────┘
        │ ① signInWithGoogle (Firebase Auth)
        │ ② callable functions (API)
        │ ③ 署名付きURLで Cloud Storage へ直接 PUT
        ▼
┌──────────────┐   ┌──────────────────────────────────────┐
│ Firebase Auth │   │ Cloud Functions (asia-northeast1)     │
│  Google のみ   │   │  - onUserFirstLogin: hd検証→Claims付与 │
│  Custom Claims│   │  - issueUploadUrl: 署名付きURL発行      │
└──────────────┘   │  - onCaptureUploaded: Storageトリガ     │
                   │  - scheduleNotifications: 毎時通知      │
                   │  - api/*: その他 callable               │
                   └───────┬──────────────────────────────┘
                           ▼
┌──────────────────┐  ┌──────────────────┐
│ Cloud Storage     │  │ Firestore         │
│ /tenants/{t}/...  │  │ /tenants/{t}/...  │
│ + CDN + Lifecycle │  │ Security Rules で  │
└──────────────────┘  │ テナント分離        │
                      └────────┬─────────┘
                               │ 23:00 JST〜
                               ▼
                   ┌──────────────────────────┐
                   │ Cloud Run Jobs            │
                   │  - vlog-generator (FFmpeg)│
                   │  - report-generator (AI)  │
                   │  - daily-aggregator (集計) │
                   └──────────────────────────┘

┌─────────────────────────────────────────────┐
│ 管理Web  Next.js（Firebase Hosting / Vercel）│
│  /admin  … テナント管理者用                    │
│  /ops    … 提供者(FREX)用                     │
└─────────────────────────────────────────────┘
```

**原則**
- リージョンは全リソース `asia-northeast1`（F-510）
- 書き込み系はすべて callable functions 経由（クライアントからFirestoreへ直接writeするのは既読フラグ等の軽微なもののみ）
- 読み取りはFirestoreへ直接（セキュリティルールで守る）
- 動画のPUT/GETはFirestoreを経由せず、署名付きURLでStorageと直接やりとり

## 3. データ設計

### 3.1 Firestore

```
/tenants/{tenantId}
  # ドキュメント本体 = テナント設定 (F-506)
  name, status(active|suspended)
  allowedDomains: string[]          # hd照合用
  timezone: "Asia/Tokyo"
  holidays: string[]                # "2026-01-01" 形式
  captureIntervalMin: 60            # 30|60|120
  workingHours: { start: "09:00", end: "18:00" }
  workTags: string[]
  reportTemplate: string
  reportDeadline: "12:00"           # 翌日のこの時刻 (F-406)
  gridSize: 4|6|9|12
  aiMode: "text" | "image"          # 既定 text (F-402)
  retentionMonths: 13
  theme: { logoUrl?, primaryColor? }

  /users/{uid}
    email, name, photoUrl
    departmentIds: string[]
    role: "member" | "deptAdmin" | "tenantAdmin"
    status: "active" | "disabled"
    crossViewDeptIds: string[]      # 横断閲覧権限 (F-604)
    fcmTokens: string[]
    joinedAt, leftAt?

  /departments/{deptId}
    name, parentId: string|null
    order: number
    overrides?: { captureIntervalMin?, workingHours?, defaultCamera? }

  /captures/{captureId}             # captureId = `${uid}_${businessDate}_${slotKey}`
    userId, departmentId

    slotKey: "12:00"                # 通知スロット
    capturedAt: Timestamp           # 秒精度。丸めない (F-105)
    status: "uploaded" | "processing" | "ready" | "deleted"
    videoPath, thumbPath
    durationSec: 2
    memo?: string                   # <=100字 (F-107)
    workTag?: string
    isLate: boolean                 # (F-110)
    deletedAt?: Timestamp           # 映像削除。ドキュメントは消さない (F-902, F-706)

  /vlogs/{vlogId}                   # vlogId = `${scope}_${targetId}_${businessDate}`
    scope: "department" | "personal"
    targetId                        # deptId or uid
    businessDate
    status: "pending" | "generating" | "ready" | "failed"
    pages: [{ videoPath, memberIds: string[] }]
    generatedAt

  /reports/{reportId}               # reportId = `${uid}_${businessDate}`
    userId, businessDate
    aiDraft: string
    aiDraftMeta: { mode, insufficientData: boolean }   # (F-408)
    body: string
    status: "draft" | "submitted"
    submittedAt?
    comments: [{ authorId, text, at }]                 # (F-407)

  /attendance/{recordId}            # recordId = `${uid}_${businessDate}`
    userId, businessDate
    workType: "normal"|"shift"|"night"|"leave"|"absent"|"remote"
    firstCaptureAt?, lastCaptureAt?
    clockIn?, clockOut?, breaks: [{start,end}]         # 明示打刻 (F-702)
    workedMinutes?
    corrections: [{ requestedBy, field, before, after,
                    status: "pending"|"approved"|"rejected", reviewedBy? }]  # (F-705)

  /dailyStats/{date}                # daily-aggregator が書く。クライアントは読むだけ
    byDept: { [deptId]: { expected, captured, rate } }

  /auditLogs/{logId}                # 追記専用 (F-805)
    actorId, action, targetPath, at
    # ルールで update/delete を全面禁止

/ops/{...}                          # 提供者側。テナント外に置く
  /tenantsIndex/{tenantId}  name, status, userCount, createdAt
  /domainIndex/{domain}     tenantId          # hd → tenant 逆引き
  /operators/{uid}          role: "ops"
```

**設計判断**
- `captureId` を決定的IDにする → 同一スロットへの二重撮影を自然に防ぎ、冪等になる
- `businessDate` を全コレクションに持たせ、**`capturedAt`から日付を導出するコードを書かない**
- 削除(F-9xx)は物理削除ではなく `status: deleted` + Storage側の実ファイル削除。枠は残る(F-902)

### 3.2 Cloud Storage

```
/tenants/{tenantId}/captures/{businessDate}/{captureId}.mp4
/tenants/{tenantId}/thumbs/{businessDate}/{captureId}.jpg
/tenants/{tenantId}/vlogs/{businessDate}/{vlogId}_p{n}.mp4
```

| 項目 | 値 |
|---|---|
| 解像度 | 720p（縦持ち 720x1280） |
| コーデック | H.264 + AAC（音声は録音するがVlog合成時に既定ミュート） |
| ビットレート | 約2Mbps |
| 長さ | 2.0秒（アプリ側で `maxDuration: 2` を強制） |

## 4. 認証・テナント分離

### 4.1 初回ログインフロー（F-501〜504）

```
1. アプリ: signInWithGoogle → Firebase Auth
2. アプリ: callable `auth-ensureTenant` を呼ぶ
3. Functions:
   a. IDトークンを検証し、`hd` クレームを取り出す
      - hd が無い（個人Gmail）→ エラー AUTH/NOT_WORKSPACE (F-504)
   b. /ops/domainIndex/{hd} を引く
      - 無い → エラー AUTH/DOMAIN_NOT_ALLOWED
   c. tenant status が active か確認
   d. setCustomUserClaims(uid, { tenantId, role })
      - /tenants/{t}/users/{uid} が無ければ role: "member" で作成（要事前登録にするかは設定で切替）
   e. 成功を返す
4. アプリ: getIdToken(true) でトークンを更新し、以降の全アクセスは Claims 準拠
```

- `hd` はGoogleが署名したIDトークン内のクレームを**サーバー側でのみ**読む。クライアント申告のドメインは一切信用しない
- Workspace側で無効化されたアカウントはトークンがリフレッシュできず、次回ログインで弾かれる（F-507）

### 4.2 Firestore セキュリティルール（骨子）

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() { return request.auth != null; }
    function tenant()   { return request.auth.token.tenantId; }
    function role()     { return request.auth.token.role; }
    function isTenantAdmin() { return role() == 'tenantAdmin'; }

    // ops配下はクライアントから一切アクセス不可（Functions/Admin SDKのみ）
    match /ops/{document=**} { allow read, write: if false; }

    match /tenants/{tenantId} {
      // ★ テナント越境の一括禁止。ここが本体
      allow read: if signedIn() && tenant() == tenantId;
      allow write: if false;   // テナント設定の変更はFunctions経由のみ

      match /users/{uid} {
        allow read: if signedIn() && tenant() == tenantId;
        allow write: if false; // Functions経由
      }
      match /captures/{id} {
        allow read: if signedIn() && tenant() == tenantId;
        // 閲覧範囲の細分化（自部署のみ等）はクエリ側+Functionsで制御し、
        // ルールでは「テナント内」までを保証する
        allow write: if false;
      }
      match /reports/{id} {
        allow read: if signedIn() && tenant() == tenantId
                    && (resource.data.userId == request.auth.uid
                        || role() in ['deptAdmin','tenantAdmin']);
        allow write: if false;
      }
      match /auditLogs/{id} {
        allow read: if signedIn() && tenant() == tenantId && isTenantAdmin();
        allow create, update, delete: if false;  // 追記もFunctionsのみ (F-805)
      }
      match /{document=**} {
        allow read: if signedIn() && tenant() == tenantId;
        allow write: if false;
      }
    }
  }
}
```

- **書き込みは原則すべて `allow write: if false`** にし、Admin SDK（Functions）だけが書く。ルールの複雑化＝穴のもと
- 部署単位の細かい閲覧制御は、まずFunctions＋クエリで実装し、ルールは「テナント境界」の保証に専念させる

### 4.3 Storage ルール（骨子）

```
match /b/{bucket}/o {
  match /tenants/{tenantId}/{allPaths=**} {
    allow read: if request.auth != null
                && request.auth.token.tenantId == tenantId;
    allow write: if false;   // PUTは署名付きURLのみ
  }
}
```

### 4.4 分離テスト（受け入れ基準 #1）

`firebase/rules-tests/` に @firebase/rules-unit-testing で以下を**最初に**書く：

1. tenantA のトークンで `/tenants/tenantB/**` の read が全コレクションで拒否される
2. Claims の無いログイン済みユーザーが何も読めない
3. auditLogs の update/delete が tenantAdmin でも拒否される
4. クライアントからの直接 write が拒否される

CIで毎回実行する。**新コレクション追加時はテスト追加をPR必須条件にする。**

## 5. API設計（Cloud Functions）

すべて callable（onCall）。認証必須、Claims の tenantId でスコープする。エラーは `code/DETAIL` 形式。

| `user-registerFcmToken` | { token } | ok | |
| `user-updateProfile` | { name?, photoUrl? } | ok | |

### 5.2 撮影（F-1xx）
| 名前 | 入力 | 出力 | 備考 |
|---|---|---|---|
| `capture-issueUploadUrl` | { businessDate, slotKey } | { uploadUrl, captureId, expiresAt } | 署名付きPUT URL(15分)。スロットの正当性（稼働時間内か、猶予内か→isLate判定）をここで行う |

## 6. 通知設計（F-101, F-114, F-116）

```
Cloud Scheduler（10分おき） → `scheduleNotifications`
  1. 全 active テナントを走査
  2. テナントのtimezoneで現在時刻を解釈
  3. 次のスロット（毎正時等、captureIntervalMin依存）が近いテナントについて:
     - 休日カレンダー該当日はスキップ（第5章運用ケース）
     - workType が leave/absent のユーザーはスキップ
     - declareOff 済みスロットはスキップ
     - 各ユーザーに 0〜3分のランダム遅延を付けて Cloud Tasks へ投入 (F-116)
  4. Cloud Tasks → FCM送信
再送 (F-114):
  - 送信15分後に再チェックするタスクを同時に積み、未撮影なら1回だけ再送
```

- 通知ペイロードには `businessDate` / `slotKey` を含め、タップで撮影画面に直行させる
- FCMトークンの無効応答は都度クリーンアップ

## 7. バッチ設計（Cloud Run Jobs）

### 7.1 vlog-generator（F-306〜309, 23:00起動）

```
入力: tenantId, businessDate
1. 対象ログ（全部署 + 全ユーザー個人）を列挙
2. ログごとに captures を slotKey 順に取得（status=ready のみ。deleted は空きコマ）
3. gridSize に従いメンバーをページ分割 (F-307)
4. FFmpeg:
   - 各コマ: scale → drawtext（氏名 + HH:mm 焼き込み, F-309）
   - 空きコマ/削除済みコマ: 生成済みのプレースホルダ静止画を2秒化
   - xstack でページ合成 → スロット順に concat
5. /tenants/{t}/vlogs/... へ保存、Firestore更新、本人へFCM (F-311)
並列度: ログ単位でタスク分割し、Cloud Run Jobs の並列実行で 7:00 までに完了させる
```

- `capture-delete` 発生時は該当Vlogを再生成キューに積む（F-905）
- 冪等：同じ vlogId への再実行は上書き

### 7.2 report-generator（vlog-generator 完了後）

```
入力: tenantId, businessDate
1. ユーザーごとに captures（時刻・memo・workTag）を収集
2. aiMode:
   - "text": テキストのみでプロンプト構築（既定, F-402）
   - "image": 各コマの thumb を最大8枚添付
3. Claude API 呼び出し:
   - システム側で reportTemplate を注入
   - コマ数 < 3 または memo 皆無 → 「情報不足」と明示させる (F-408)。創作禁止を明記
4. reports/{uid}_{date} に aiDraft として保存（status: draft）
5. 朝、本人へ「日報案ができました」通知。締め時刻前に未提出ならリマインド (F-406)
```

プロンプトは `jobs/report-generator/prompts/` にファイルとして置き、テンプレをコードから分離する。

### 7.3 daily-aggregator（日次 05:00）

- 撮影率（期待スロット数＝稼働時間・休日・workType から算出した分母）を dept 単位で集計し `dailyStats` へ
- 単一ドキュメントへの高頻度カウントを避けるため、リアルタイム集計はしない

## 8. モバイルアプリ設計

### 8.1 画面と遷移（expo-router）

```
(auth)/login                 … Googleでログインのみ
(tabs)/
  home                       … カウントダウン、当日の自分のコマ、日報ステータス (F-801)
  log/[deptId]               … サムネイルグリッド (F-301〜305)
      └ capture/[captureId]  … 単体再生 + 削除 (F-303, F-901)
  vlog/[vlogId]              … ページ送りプレイヤー、書き出し・共有 (F-310〜312)
  report/[businessDate]      … AI案の編集・提出 (F-404)
  attendance                 … 当月稼働、区分申告、修正申請
settings                     … 通知、カメラ既定、撮影しない時間
capture-modal                … 通知タップで直行。カメラ→2秒録画→メモ/タグ→送信
history                      … カレンダー → 過去のVlog/日報
```

### 8.2 撮影フロー実装

```
1. 通知タップ → capture-modal を businessDate/slotKey 付きで開く
2. expo-camera: maxDuration 2 で録画（録画ボタン1タップ、2秒で自動停止）
3. 録画完了 → プレビュー2秒 → メモ/タグ入力（スキップ可）
4. `capture-issueUploadUrl` → 署名付きURLへ PUT（バックグラウンド継続を考慮し
   expo-file-system の resumable upload を使用）
5. 成功 → `capture-commit`
6. 失敗/オフライン → ローカルキュー（SQLite）へ。capturedAt は撮影時点を保持 (F-112)
   アプリ起動時・フォアグラウンド復帰時・ネット復帰イベントでキューを再送
```

- 撮り直しはアップロード前のみ可。コミット後は削除→撮影猶予内なら再撮影
- カメラロールへのアクセス権限はそもそも要求しない（F-106 を構造的に保証）

### 8.3 サムネイルグリッド（F-301〜305）

- FlashList でメンバー行 × スロット列（または設定分割数のタイル）を仮想化描画
- 画像は thumb(jpg) のみ。**動画コンポーネントをグリッド内に置かない**
- 分割数切替（4/6/9/12）はタイルサイズの変更として実装
- 未撮影=グレー枠、削除済み=「削除済み」枠、遅延=バッジ

### 8.4 状態管理・共通

- サーバー状態: TanStack Query（callable + Firestore listener のラッパー）
- ローカル: zustand（アップロードキュー、下書き）
- 全日時は dayjs + timezone プラグインで**テナントtimezone**で表示

## 9. 管理Web設計（Next.js）

| パス | 対象 | 主要機能 |
|---|---|---|
| /admin | tenantAdmin | ユーザーCRUD、部署ツリー編集、テナント設定（F-506全項目）、休日カレンダー、勤怠CSV、監査ログ閲覧 |

- /ops からテナント業務データ（動画・日報）への導線は作らない（F-509）

## 10. エラーコード・共通仕様

| code | 意味 |
|---|---|
| AUTH/NOT_WORKSPACE | 個人Gmailでのログイン |
| AUTH/DOMAIN_NOT_ALLOWED | 未登録ドメイン |
| AUTH/TENANT_SUSPENDED | テナント停止中 |
| CAPTURE/SLOT_CLOSED | 猶予超過（後追いは isLate で受理） |
| CAPTURE/DUPLICATE | 同一スロット撮影済み |
| UPLOAD/EXPIRED | 署名URL失効 → 再発行 |
| REPORT/DEADLINE_PASSED | 締め後の提出（受理するが遅延フラグ） |

- callable のリトライ：クライアントは冪等なAPI（issueUploadUrl等）のみ指数バックオフで最大3回
- ログ：Functions/Jobsは構造化ログ（tenantId, uid, action）。**動画の中身・memo本文はログに出さない**

## 付録A. FFmpeg xstack 生成例（12分割・参考）

```bash
# コマごとに前処理（氏名+時刻焼き込み）
ffmpeg -i in.mp4 -vf "scale=360:640,drawtext=text='山田 12\:04':x=10:y=h-40:fontsize=24:fontcolor=white:box=1:boxcolor=black@0.5" -an pre_01.mp4

# 12コマを 3x4 で合成（レイアウト定義はページ人数に応じて動的生成）
ffmpeg -i pre_01.mp4 ... -i pre_12.mp4 \
  -filter_complex "xstack=inputs=12:layout=0_0|w0_0|w0+w1_0|0_h0|w0_h0|w0+w1_h0|0_h0+h1|w0_h0+h1|w0+w1_h0+h1|0_h0+h1+h2|w0_h0+h1+h2|w0+w1_h0+h1+h2" \
  -c:v libx264 page1_slot1200.mp4

# スロット順に concat
ffmpeg -f concat -safe 0 -i list.txt -c copy vlog_dept_2026-07-26_p1.mp4
```

レイアウト文字列の生成関数は `jobs/vlog-generator/src/layout.ts` に実装し、単体テストを付ける。
